# Twi AI Annotation — Sentiment & Intent

A practical Twi language annotation project demonstrating how text can be labeled for sentiment, intent, ambiguity, and quality control in AI training workflows.

## Project Overview

This project demonstrates a small-scale annotation workflow for Twi language data.

The goal is to show how a language dataset can be consistently labeled using clearly defined annotation guidelines while accounting for context, sentiment, intent, and ambiguous language.

The dataset is designed as a portfolio demonstration and is not intended to represent production training data.

## Annotation Tasks

The project focuses on:

- Sentiment classification
- Intent classification
- Twi language understanding
- Ambiguous text identification
- Annotation consistency
- Quality control
- Structured dataset preparation

## Sentiment Labels

Each example can be assigned one of the following sentiment labels:

- **Positive** — expresses satisfaction, happiness, approval, or a favorable opinion.
- **Negative** — expresses dissatisfaction, frustration, anger, disappointment, or an unfavorable opinion.
- **Neutral** — primarily provides information, asks a question, or does not clearly express positive or negative emotion.

## Intent Labels

Examples may be categorized according to their primary intent, such as:

- **Pricing**
- **Purchase**
- **Delivery**
- **Complaint**
- **Information Request**
- **Feedback**
- **Cancellation**
- **Other**

## Annotation Principles

Annotations should be based on the meaning and context of the text rather than individual words alone.

When an example is ambiguous:

1. Consider the complete sentence.
2. Identify the most likely intended meaning.
3. Select the most appropriate label.
4. Record the ambiguity when necessary.
5. Avoid making assumptions that are not supported by the text.

## Quality Control

Quality is maintained by:

- Using consistent annotation definitions
- Reviewing difficult examples
- Checking for conflicting labels
- Separating clear examples from ambiguous examples
- Documenting annotation decisions
- Performing a final review before including data in the dataset
